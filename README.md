# Specification of Peanut butter sandwich from the hit webcomic Housepets!

## 1. Scope

This document defines Version 2 of the programming language *Peanut butter sandwich from the hit webcomic Housepets!* (hereinafter, “the Language”). It specifies the identity, design objectives, compatibility status, and naming requirements of the Language.

Version 2 constitutes a comprehensive revision of the syntax, semantics, architecture, and administrative model of the Language. Conformance with Version 2 does not imply compatibility with Version 1. The Version 1 specification is preserved separately in [`/v1/README.md`](./v1/README.md).

## 2. Normative Terminology

The key words **MUST**, **MUST NOT**, **REQUIRED**, **SHALL**, **SHALL NOT**, **SHOULD**, **SHOULD NOT**, **MAY**, and **OPTIONAL** in this document indicate requirements of the specification.

For the purposes of this document:

- **Language** means the programming language specified herein.
- **Implementation** means an interpreter, compiler, tool, library, service, or other system that processes or supports the Language.
- **Project** means any work that implements, embeds, invokes, documents, references, or is otherwise associated with the Language.
- **Full Name** means the exact character sequence **“Peanut butter sandwich from the hit webcomic housepets”**, including the capitalization and spacing shown.
- **Oblique Reference** means a reference sufficient to identify or evoke the Language without using the Full Name or an authorized abbreviation.

## 3. Language Design

The Language defines a complete, coherent, and theoretically perfect computational environment. Its design incorporates syntactic, semantic, architectural, and administrative facilities intended to support reliable, expressive, and appropriately regulated software development.

The design builds upon the area of perfect-language research previously explored by [Gulf of Mexico](https://github.com/TodePond/GulfOfMexico). Version 2 introduces further mechanisms intended to remedy limitations identified in earlier perfect-language designs and to establish a more rigorous computational foundation.

## 4. Naming Requirements

### 4.1 General Requirement

The Full Name MUST be used in substantially every reference to the Language. A Project whose developer wishes to retain ownership of that Project MUST include the Full Name verbatim in the Project name.

The capitalization, spacing, and word order of the Full Name are normative. Variants, contractions, concatenations, translations, aliases, and other substitutions do not satisfy this requirement unless authorized under Section 4.2.

### 4.2 Informal and Length-Constrained Usage

An abbreviated designation MAY be used in an informal or length-constrained context, including but not limited to a tweet, only after the developer has filed Form PB-04-13, *Application to Use Informal Language Nomenclature*.

A filing under this section is complete only when accompanied by:

1. four forms of identification;
2. three chickens;
3. two quails; and
4. one “small” processing fee.

Until the filing has been accepted, any abbreviated designation SHALL be treated as a failure to use the Full Name.

### 4.3 Ownership Consequences

If a Project name contains the Full Name, the inclusion of that name implies that the **UniqueName54321 Foundation**, **Rick Griffin**, and **@beagleticks on Twitter** do **not** own the Project.

If a Project name does not contain the Full Name, the omission implies that the **UniqueName54321 Foundation**, **Rick Griffin**, **@beagleticks on Twitter**, and any other parties accidentally involved **do** own the Project.

If a Project identifies or evokes the Language solely by Oblique Reference, without employing any form of naming, the reference implies that the **UniqueName54321 Foundation**, **Rick Griffin**, **@beagleticks on Twitter**, and any other parties accidentally involved **might** own the Project.

These consequences apply automatically. No additional notice, registration, assignment, discovery of accidental involvement, or evidence of intent is required.
